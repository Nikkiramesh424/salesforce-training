# Day 12 – Salesforce DX and Professional Workflow

### Objective
The objective of Day 12 was to understand how professional Salesforce developers work in real enterprise environments using:
- Salesforce DX
- Command Line Interface (CLI)
- GitHub
- Source-driven development
- Team collaboration workflows

---

# What is Salesforce DX?

Salesforce DX (Developer Experience) is a modern development approach that helps developers build Salesforce applications using source-driven development.

Salesforce DX provides:
- Better developer productivity
- Version control integration
- Modern deployment workflow
- Team collaboration support
- Scratch org and sandbox management

It helps enterprise teams develop Salesforce applications efficiently and professionally.

---

# Why CLI Matters

The Salesforce Command Line Interface (CLI) allows developers to interact with Salesforce orgs directly from the terminal.

Benefits of CLI:
- Faster development workflow
- Easy deployments
- Automation support
- Better developer productivity
- Simplified testing and debugging
- Script-based operations

CLI tools help developers perform tasks quickly without depending completely on browser clicks.

---

# Why GitHub Matters

GitHub is important because enterprise software development requires collaboration between multiple developers.

GitHub helps with:
- Version control
- Team collaboration
- Backup of source code
- Change tracking
- Branch management
- Rollback support

Without GitHub, managing large projects becomes difficult and risky.

---

# Developer Workflow Thinking

Professional developers use:
- GitHub
- CLI
- Salesforce DX

instead of only browser clicks because enterprise projects require:
- Collaboration
- Version tracking
- Deployment management
- Automation
- Reliability
- Scalable workflows

Source-driven development is more efficient than manual browser-based customization.

---

# Team Collaboration Thinking

Suppose 10 developers work on the same Salesforce project.

Without:
- version control
- branches
- deployment workflow

the following problems may happen:

| Problem | Explanation |
|----------|-------------|
| Code conflicts | Multiple developers may overwrite each other's work |
| Data inconsistency | Different environments may become unsynchronized |
| Lost changes | Important updates may disappear |
| Deployment failures | Incorrect deployments may break production |
| No rollback | Failed changes cannot be reverted easily |
| Difficult collaboration | Team productivity decreases |
| Testing issues | Unverified code may reach production |

# Revision Questions

## 1. Why do enterprise teams use version control?
To manage source code changes and support team collaboration.

## 2. Why is deployment workflow important?
It ensures safe and reliable deployment to production systems.

## 3. What problems happen without collaboration tools?
Code conflicts, lost work, and deployment failures may occur.

## 4. Why is Salesforce DX important?
It enables modern source-driven Salesforce development.

## 5. Why do developers prefer CLI tools?
CLI tools improve productivity and automation.

## 6. Why do enterprise systems require rollback capability?
To recover safely from deployment failures.

## 7. Why should teams separate development and production?
To prevent unstable code from affecting live users.

## 8. Why is source-driven development useful?
It improves version control and deployment management.

## 9. Why is collaboration difficult in large projects?
Because multiple developers work on shared codebases simultaneously.

## 10. Why is engineering workflow important?
It ensures reliability, scalability, and maintainability.
